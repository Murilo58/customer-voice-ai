## Testes

48 testes automatizados, todos aprovados (`npm test`), nos dois drivers (`neon` pelo pooler e `pg` por conexão direta):

- **Unitários (10):** tokens e hash, UUIDv7, normalização, mascaramento, permissões, estado de convites, mensagens, verificação estática.
- **Isolamento (11):** papel sem `BYPASSRLS`; falha fechada sem contexto; cada organização vê só os próprios dados nas 4 tabelas de tenant; WITH CHECK; FK composta; UPDATE sem filtro; contexto não sobrevive a COMMIT/rollback; 60 transações concorrentes; políticas de pré-contexto sem escrita.
- **Auditoria (7):** runtime não altera nem exclui; trigger bloqueia até o dono do schema (UPDATE, DELETE, TRUNCATE); mascaramento; eventos de autenticação inseríveis mas não legíveis pelo runtime; contexto de Superadmin restrito.
- **Organizações (15):** CA-01.1, CA-01.2, CA-02.1 (negação auditada), CA-02.2, CA-02.4 (sem equipes), convite cancelado, aceites concorrentes, identificador duplicado, último Administrador, mudança de perfil auditada.
- **Better Auth (5):** UUIDv7, hash de senha, senha curta recusada, CA-02.3 com duas sessões, cadastro público bloqueado por HTTP.
- **Smoke HTTP** (`next start`): redirecionamentos sem sessão, cabeçalhos de segurança, endpoint N7 fechado sem token.

## Decisões técnicas tomadas no I-0 (dentro da arquitetura documentada)

1. **Sem o plugin de organização do Better Auth.** O DATA_MODEL define `memberships` e `user_invitations` como tabelas de tenant com RLS; as tabelas do plugin ficariam fora do RLS.
2. **Pré-contexto por políticas de leitura, não por `SECURITY DEFINER`.** Com `FORCE ROW LEVEL SECURITY`, funções `SECURITY DEFINER` também são filtradas. As consultas "de quais organizações sou membro" e "convite pelo token" usam `app.user_id` e `app.invitation_token_hash`, locais à transação, com políticas somente de leitura. Nenhum papel recebe `BYPASSRLS`.
3. **Eventos de autenticação sem organização** são inseridos pelo runtime sem `RETURNING` (política `auth_events_insert`) e só o Superadmin os lê.
4. **Cadastro só por convite:** as rotas HTTP do Better Auth ficam numa lista restrita; cadastro, login e 2FA passam por server actions auditadas.
5. **TypeScript 6.0.3** (não a 7.x nativa) por compatibilidade com o ecossistema; todas as versões têm ao menos duas semanas de publicação; Better Auth 1.7.14 já inclui as correções de todos os avisos de segurança publicados até 10/11/2026.
